# 01 · 需求与成功标准

## 用户、目标与范围

员工询问制度或产品问题，得到可核验答案、引用原文、资料缺口与任务状态。输入包括问题及可选历史，材料必须是带文档 ID 与版本日期的合成 FAQ/制度。

本项目覆盖制度期限、报销材料、产品导出、密码重置、远程办公等合成资料。它不验证真实企业制度，不接入隐私文档。

## 验收映射

| 验收要求 | 实现与证据 |
|---|---|
| 明确答案 | normal：读取 D01 后回答 30 天 |
| 文档冲突 | conflict：D01/D02 同时列出，不根据日期裁决 |
| 资料外问题 | outside：年终奖无依据，改写检索后报告资料不足 |
| 改写后的相似问题 | paraphrase：口语化问法仍定位 D01 |
| 上下文追问 | context：先问期限，再追问材料；保存前置运行 |
| 工具失败 | search_failure/read_failure：真实模型观察注入的本地工具错误 |
| 证据替换 | changed：D01 内容改为 45 天后答案变化 |
| 上限 | budget：1 次决策预算后明确 incomplete |
| 范围限制 | scope：不得把正式员工政策套用到试用期 |
| 真正动态决策 | LangGraph 循环内每次动作由 DeepSeek 返回；Trace 记录实际参数与结果 |
| 离线入口 | 显式 mock 参数/页面模式，不自动代替真实模型 |

## 成功标准

1. 关键政策结论有原文支持，引用 ID、版本和片段可精确定位。
2. 无法核验时不输出确定性政策答案；必须区分资料不足、冲突、澄清、工具失败和系统失败。
3. 真实模型观察不同工具结果后产生不同路径；不能用脚本日志冒充模型决策。
4. 运行在时间、模型调用次数与工具次数预算内终止，保留已有证据。
5. 一仓库提供源码、依赖、五份文档、测试与至少三组实际输入/输出/Trace，覆盖全部验收点。

## 交付约束

GitHub 仓库由用户指定为 `xiaoqifabaowa/xiaoying`。提交邮箱由用户指定，真实密钥仅保存在忽略的本地 `.env`。题目文件没有数字题号，本项目不编造题号。最终 SHA 在交付时提供。

## 非目标

身份认证、部门数据权限、PDF/OCR、企业文档接入、多人协作、外部搜索、Embedding、微服务和云部署均不属于本次已实现范围。
